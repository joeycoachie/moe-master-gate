# Founder Command · The Operator's Playbook

This folder is the **Founder Command window**: the hub above every product. The founder (Joey, "the Architect") works here on cross-product decisions, the domain, and anything that touches more than one product.

## Read first, every session

1. `REGISTRY.md`: every product, folder, repo, live link and database.
2. `DECISIONS.md`: settled calls. Don't re-ask them.
3. The last ~30 lines of `LEDGER.md`: what the other windows did recently.

## What this window does

- Cross-product work: the domain and subdomains, Founder Command, retiring duplicates, consolidating products.
- Keeps REGISTRY, DECISIONS and LEDGER true.
- May read any product folder listed in REGISTRY. Before *changing* a product, check its git status and LEDGER for recent work by another window, and follow that product's own rules (e.g. RECUP.STN pushes only on the founder's say-so).
- Day-to-day building of a single product belongs in that product's own window.

## How the founder sends work ("transmissions")

- **New protocol week** → goes to the M.O.E. Terminal Armory. Send: the file, ID, arc, week, and what it replaces (if anything). Missing fields are read from the file itself.
- **New product or agent** → gets a subdomain (see REGISTRY → Domain). Its folder gets the hub rule (`HUB_RULE.md`) in its CLAUDE.md, and a row in REGISTRY.

## Rules

- Append a LEDGER line after every push, deploy, DNS change or migration. Commit and push the hub.
- Never repoint `www`/root of theoperatorplaybook.com (Gumroad store), and never move the nameservers.
- Plain words with the founder. They send long, multi-part messages: sort them into now / next / later, and answer in their own doctrine's terms (D-002 Base Camp, SYS-D020 naming).
